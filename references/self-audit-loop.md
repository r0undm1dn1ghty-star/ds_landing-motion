# Самоаудит-луп: как найти, где вьебался, без посторонней помощи

Зачем: скилл должен работать даже на слабой модели. Поэтому цикл — не «посмотри и оцени», а механические проверки с числами и списками, где каждый шаг даёт следующий. Оценка «на глаз» разрешена только как СЛЕД, который потом подтверждается замером.

## Цикл (максимум 3 круга)

```
сборка
  └→ 1. АВТОГЕЙТ: python demo/measure.py --shot-dir demo/_shots
        ├ упал → чинить по списку падений, НЕ добавляя эффекты
        └ закрыт → 2. ВИЗУАЛЬНЫЙ ПРОТОКОЛ
              └→ 3. ОЦЕНКА РЫЧАГОВ (8 из motion-rhythm-qa.md)
                    └→ 4. ПЕРЕСБОРКА: только 2–3 слабейших момента
                          └→ назад к 1. Круг закрыт
```

**Стоп-условия:** гейт закрыт И ни один рычаг < 3 → сдать. Или 3 круга исчерпаны → сдать с честным списком остаточных слабостей (что не дотянуто и почему), а не с «всё супер».

## Шаг 1. Автогейт (без глаз)

`demo/measure.py` печатает 26+ проверок. Каждое падение — конкретная причина: пустой блок (ink < 2%), переполнение по X, reduce-ветка не отдаёт финал, детерминизм не сошёлся. Чинить причину, а не симптом: падение «контур пуст» лечится геометрией, а не подгоном числа.

## Шаг 2. Визуальный протокол (глаз = след, не вывод)

Смотреть: полный кадр 1440, мобильный 390, спорный блок крупно (4×), кадр reduce. Находка глаза сначала ПРОВЕРЯЕТСЯ: пиксель-скан (какой цвет/доля), `getComputedStyle` (radius, вес, тень), `ink_by_region`. Только подтверждённая находка становится задачей.

Типовые собственные косяки и как их ловить самому:

| Косяк | Как поймать | Как чинить |
|---|---|---|
| Блок пуст на экране, числа живые | `ink_by_region < 2%` при честной пробе | ресайз обязан перерисовывать; контент виден без JS |
| Канвас очищен, проба показывает цифры | смена `canvas.width/height` без перерисовки | `ResizeObserver` → fit + redraw (см. `verify-motion.md` §9) |
| Второй стенд/страница «заодно» | появился новый html рядом с demo/index.html | влить секцией, стенд удалить |
| Фиолетовый неон по чужому совету | пиксель-скан: hue 240–290 в кадре | палитра канона, совет отклонить |
| Bounce/elastic | `grep -nE "bounce\|elastic"` | ease-out токен |
| Анимация layout-свойств | `transition:[^;]*(width\|height\|top\|left)` | transform/opacity |
| Одинаковый entrance у секций | два `.rv` с одинаковым классом движения | одно движение-момент на секцию |
| Reduce сломан | прогон `?reduce=1` даёт движение/пустоту | финальное состояние мгновенно |
| «Числа есть, кадра нет» | скриншот спорного блока крупно | живой браузер как арбитр (verify-motion §6) |
| JS падает на отсутствующем узле, окно пустое | `TypeError: null.classList` в консоли, 0 карточек | ensure-функция создаёт скелетоны в `startState`, все обращения через null-гарды |
| `aria-label` не равен тексту (NBSP-джойнер) | сравнить коды: 32 vs 160 по позициям | один источник строки: `textContent` → `aria-label`, только обычные пробелы |
| Постер уничтожен до автоплея: луп стартует с пустого окна | без JS постер полный, с JS первые секунды пусто | `startState` оставляет скелетоны, постер в HTML — финал (`data-state="payoff"`) |
| «Огромные пустоты между блоками» в вердикте vision | замер `getBoundingClientRect` даёт 18/24/18 px — ритм нормальный | НЕ чинить: находка про геометрию без числа = галлюцинация модели; сначала цифры, потом правка |
| Витрина проходит гейт, но в кадре 4 карточки из 7 | гейт считает «не пусто», не «всё влезло» | приёмка только по кадру: считать видимые узлы на скриншоте и сверять с брифом |
| Подписи в 3D висят вокруг фигуры и лезут друг на друга | на кадре бирка пересекает соседнюю/уезжает за край | увести подписи из 3D в список рядом со сценой (см. ниже) |

## Шаг 2б. Приёмка витрины — отдельный протокол

Витрина (страница-шоукейс, самостоятельный html) проходит гейт иначе, чем демо внутри скилла: главный дефект витрины — композиция, а её числа не ловят.

1. **Снять кадр 1440×1000 и 390** в `file://` (headless Chrome), посмотреть его vision-моделью (`ollama-cloud-vision`, `gemma4:31b`).
2. **Спросить по пунктам, а не «как выглядит»:** сколько узлов/карточек видно и все ли целиком · не перекрывает ли текст графику · не срезано ли краем · читается ли легенда · годится/чинить. Ответ без числа «сколько» — не приёмка.
3. **Сверить число видимого с брифом:** 7 карточек в брифе — 7 в кадре. Витрина, где видно 4, не «почти готова», а не готова.
4. **Каждую находку про отступы/размеры проверить замером** до правки: вшить пробник (`window.load` → `getBoundingClientRect` в `document.title`) и снять `--dump-dom`, либо посчитать по CSS. Модель систематически преувеличивает «пустоты» и неверно оценивает пропорции.
5. **Правки по приоритету:** обрезка/перекрытие → иерархия и читаемость → моушн → отделка. После правки — новый кадр и тот же вопрос; старый вердикт не переиспользовать.

## Шаг 3. Оценка рычагов

Из `motion-rhythm-qa.md`: easing, стаггер, ритм-грамматика, камера/глубина, типографика, палитра, отделка, сдержанность. Каждому 1–5, назвать 2–3 слабейших. Оценка — цифрой, не прилагательным.

## Шаг 4. Пересборка слабейших

Правило одного изменения за круг: меняем худший рычаг (или связку из 2–3), НЕ трогаем остальное — иначе не видно, что помогло. Пересборка короткого участка, не всего.

## Шаг 5. Отчёт круга (обязательный, 3 строки)

```
Круг N: нашёл [числа] → поменял [одно] → стало [числа]
```
Без отчёта круг не засчитан. После стопа: что сдано, что осталось слабым, почему.

## Почему это работает на слабой модели

Каждый шаг — либо число с порогом (гейт, ink, рычаги), либо список с грепами, либо фиксированный протокол просмотра. Нет шагов, требующих «чувства». Модель любого уровня проходит цикл и получает результат лучше стартового; сильная модель проходит его быстрее и глубже.
