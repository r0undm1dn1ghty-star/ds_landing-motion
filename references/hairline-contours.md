# Линия как материал: контуры (marching squares)

Способ получить графику из ЧИСЛОВОГО ПОЛЯ: берём `field(x,y) -> число` и рисуем линии уровня. Никаких картинок, никаких библиотек — 60 строк на JS. Даёт топографический рельеф, «гравированный» портрет, гравюру по фото, радарные кольца, обводку логотипа из альфа-канала.

**Зачем в лендинге:** это самый сильный приём из семейства hairline — он выглядит как чертёж, а не как генерация. Плотность линий несёт смысл (высота, яркость, расстояние), а не декор. Источник приёма — набор `frankenstein-animator` (автор — Claude), код перенесён как есть: `demo/contours.js`.

## Что строит

| Поле | Что получается | Где применять |
|---|---|---|
| `fbm(noise, ...)` | топографический рельеф | фон секции, hero-пейзаж, «карта рынка» |
| яркость картинки | гравированный портрет / гравюра | портрет основателя, обложка кейса |
| альфа-канал PNG | обводка логотипа / плоской графики | лого-герой, схема из иконки |
| расстояние до точки | радарные кольца, «зоны охвата» | карта покрытия, радиус сервиса |
| глубина 3D-сцены | контурная обводка модели | hero с объектом |

## Ядро: marching squares

16 случаев по четырём углам ячейки, два «седла» (5 и 10) разрешаются средним по ячейке. Код — `demo/contours.js`, API:

```js
Contours.mulberry32(seed)                    // детерминированный PRNG
Contours.makeNoise(seed)                     // value noise, период 256
Contours.fbm(noise, x, y, octaves)           // 0..1, фрактальная сумма
Contours.contourSegments(field, w, h, cols, rows, level)  // -> [x1,y1,x2,y2, ...]
Contours.segmentsToPath(segment, digits)     // -> строка SVG `d`
```

Правило: `contours.js` — ОДИН файл без зависимостей, подключается первым. Не тащить ради этого d3-контуры или состоявшуюся библиотеку.

## Тонкая линия: правила, без которых всё поедет

- **1 логический пиксель = `1 / devicePixelRatio` CSS-пикселей.** Прописать в `--hair` и использовать в `stroke-width: var(--hair)`. При DPR 2 линия станет 0.5 CSS px — это и есть «один пиксель экрана».
- **`vector-effect: non-scaling-stroke`** на каждой линии. Без него любой `transform: scale()` утолщает штрих, и вся хайрлайновая сетка превращается в жирную кашу.
- `shape-rendering: geometricPrecision`, `stroke-linecap: round`, `fill: none`.
- Слои **обязаны вылезать за вьюпорт** (в шаблоне запас 12%): параллакс двигает слои, и без запаса из краёв вылезают пустые поля.
- Число уровней > 9 на слой даёт муар на плотном участке. Рабочее — 5–7.

## Параллакс: глубина это разница скоростей

Слой получает глубину `d` в (0,1], где 1 — ближайший. Курсор `p` в [−1,1], прогресс скролла `s` в [0,1]:

```
offset_i = p * d_i * A          // A — сдвиг ближайшего слоя в px (в шаблоне 26)
scale_i  = 1 + s * d_i * Z      // Z — «долли» (в шаблоне 0.55)
```

Проверено замером: сдвиг слоя масштабируется ровно по `d` — от 4.02 px при `d = 0.2` до 20.1 px при `d = 1.0`.
Ближний слой — мельче частота шума, выше непрозрачность (`opacity ≈ 0.22 + 0.6·d²`), светлее оттенок.

## Читаемость текста поверх плотной графики

Плотная сетка линий под текстом убивает контраст, даже когда сам текст белый. Лечится не уменьшением линий, а **подложкой-скримом**: радиальный градиент в тон фона за блоком текста.

```css
.copy::before{content:"";position:absolute;inset:-36px -48px;z-index:-1;border-radius:50%;
  background:radial-gradient(closest-side, #07080de6 40%, #07080d00)}
```
Плюс `text-shadow` в тон фона. Этот баг был найден на живом шаблоне и починен — без скрима текст нечитаем.

## Цена

Число сегментов ≈ `cols × rows × levels × layers`. Замер: сетка 110×69, 7 уровней, 5 слоёв → **17 285 сегментов, 409 КБ данных пути, ~244 мс** на сборку в headless Chromium. Считать до сборки: на мобиле это уже ощутимо, поэтому сетку брать 80×50, слоёв 3–4.

## Проверка движка

Движок проверялся против аналитической окружности: максимальная радиальная ошибка **0.007**, периметр **94.222** против точных **94.248**. То есть контуры честные, а не «примерно похоже».

## Пишем в видео — отдельные грабли

`yuv420p` вдвое режет цветовое разрешение, и тонкие линии в нём рассыпаются:
- держать линии почти белыми/серыми (насыщенный акцент в хайрлайне умирает первым);
- рендерить в 2× и уменьшать lanczos;
- CRF начинать с 16, проверять на 100%-кропе контакт-листа;
- тонкие ГОРИЗОНТАЛЬНЫЕ линии мерцают — прогонять `scripts/motion_qa.py` и смотреть на всплески.

## Чего не делать

- Не ставить `dpr` в `devicePixelRatio` для фонового слоя — только для хайрлайна, и только через `non-scaling-stroke`.
- Не анимировать `stroke-width` — это layout-подобная работа на каждой линии. Только `transform`/`opacity` родителя.
- Не забывать `prefers-reduced-motion`: убрать сдвиг по курсору и долли, оставить статичный кадр.
- Не строить контуры на гигантской сетке «чтобы было красиво» — платит мобильный.
