# Детерминированное движение: кадр = чистая функция времени

Главный принцип, который отличает моушн «который снимают» от моушн «который живёт на странице». Источник — набор `frankenstein-animator` (Claude), здесь адаптировано под лендинг.

## Правило

**Состояние в момент `t` — ЧИСТАЯ ФУНКЦИЯ `t` и зерна. Никакого накопления от кадра к кадру.**

```js
// НЕПРАВИЛЬНО: частица помнит себя
p.x += p.vx * dt;

// ПРАВИЛЬНО: позиция считается от времени
function pos(p, t) {
  return [
    ((p.x + p.vx * t / 2 + Math.sin(p.a + t * 1.3) * 0.03) % 1 + 1) % 1,
    ((p.y + p.vy * t / 2) % 1 + 1) % 1
  ];
}
```

## Почему это важно именно на лендинге

1. **Реверс и скраб работают.** Прокрутил назад — кадр корректный, а не «докрученный от последнего».
2. **`prefers-reduced-motion` даёт точное ФИНАЛЬНОЕ состояние** — просто `pos(p, t_final)`, а не пустоту.
3. **Фоновая вкладка не врёт.** Накопительная анимация в неактивной вкладке не тикает: витрина показывает «0 заявок, 0 клиентов» — и это уже ловилось на живом лендинге.
4. **Повторяемость.** Один и тот же вход даёт один и тот же кадр → скриншот-тест и DOM-проба сравнимы между прогонами.
5. **Готово к видео.** Если потом это уедет в ролик, кадры можно считать параллельно и в любом порядке.

## Зерно вместо `Math.random`

`Math.random()` запрещён — он делает кадр неповторяемым. Нужен seeded PRNG:

```js
function mulberry32(a) {
  return function () {
    a = (a + 0x6D2B79F5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
```

Смещение дрейфа: `((Math.floor(t*30) - k*2) % F + F) % F` — так «хвост» из подкатывающихся кадров не уходит в минус.

## Замкнутые пружины вместо физики

Пружина с перерегулированием считается формулой, а не пошаговым интегратором:

```js
// z = затухание, om = частота
function spring(t, z = 0.42, om = 16) {
  if (t <= 0) return 0;
  const wd = om * Math.sqrt(1 - z * z);
  return 1 - Math.exp(-z * om * t) * (Math.cos(wd * t) + (z * om / wd) * Math.sin(wd * t));
}
```

Кавычка стаггера — элементу `i` даётся задержка `i * 3` кадра (≈100 мс при 30 fps), а не таймер. Каждый элемент — своя пружина от своего нуля.

## Биения вместо магических секунд

Резать и переключать по битам, а не «через полсекунды»:

```
кадров на бит = fps * 60 / bpm        // 120 bpm при 30 fps = 15 кадров
```

При 30 fps: `1800 / bpm`. Резы обязаны попадать на целые кадры, поэтому дрейф считается, а не угадывается:

```
fpb = 1800 / bpm;  drift = fpb - round(fpb);
// |drift| ≈ 0  -> резы ровно по биту
// иначе        -> кадр мимо каждые 1/|drift| битов
```

На лендинге это читается так: тикеры, счётчики, прогресс-бары и пульсации должны идти по одной битовой единице, а не у каждого своя длительность.

## Контракт «посмотреть состояние на момент t»

Если страницу потом снимают (скриншоты, тесты, видео), нужен один вход:

```
window.__seek(t)  ->  DOM/канвас показывают состояние РОВНО на t секунд, ничего не висит в очереди
```

Виртуальный клок подменяет `performance.now`, `Date.now`, `requestAnimationFrame`, `Math.random` (на seeded) и ставит CSS-анимации на `currentTime = t`. Реализация-референс — `scripts/seek-shim.js` (в скилле, вызывается как есть).

**Чего шим НЕ покрывает** (знать до того, как обещать): `new Date()` без аргументов, `setTimeout`/`setInterval`, элементы `<video>`/`<audio>`, веб-шрифты, сохранение WebGL-буфера, воркеры. Если эффект опирается на это — он не детерминирован, и так и надо сказать.

## Запреты

- Состояние между кадрами (физика «от предыдущего кадра») — нет. Замкнутая формула, либо пересчёт от нуля, либо запечённые данные.
- `Math.random()`, `Date.now()`, `performance.now()` внутри эффекта — нет.
- `setTimeout`/`setInterval` как источник движения — нет.
- Разные единицы ритма у соседних эффектов — нет.
